# Sprint 8 — Behavioural Model Layer (FSM + Dependency Graph)

## Goal

Add an explicit **behavioural layer** to the Agent Map: a tool-dependency graph with typed edges (requires, mutually_exclusive, commonly_precedes) and, where traces are available, a **finite-state machine (FSM) abstraction** of the agent's decision flow. The current Agent Map is a containment/invocation graph — it shows what the agent *has*, not how it *behaves*. Model-based testing literature (Walkinshaw et al.; EFSM inference) shows that the representation determines achievable coverage: FSMs support transition coverage, du-path coverage, and boundary coverage.

**Depends on**: Sprint 2 (preconditions for dependency typing) + Sprint 7 (traces for FSM inference).

## Why This Matters for Phase B

- **Tool-dependency graph** enables multi-step scenario generation: "call A, then B, then C" chains
- **Mutually exclusive edges** prevent impossible test combinations
- **Circular dependency detection** generates stress tests for infinite loops
- **FSM states** give Phase B transition-coverage criteria: "test every state transition at least once"
- **Long-horizon scenarios** can be generated by walking the FSM to cover all paths

## Tasks

### 8.1 Define Behavioural Model Data Structures

**File**: `src/graph/behavioural_model.py` (new file)

- [ ] Define data structures:
  ```python
  @dataclass
  class DependencyEdge:
      source_tool: str
      target_tool: str
      edge_type: str              # "requires" | "commonly_precedes" | "mutually_exclusive" | "enables"
      weight: float               # strength of relationship (0.0-1.0)
      evidence: str               # "static" | "ai_inferred" | "trace_mined" | "combined"
      description: str            # human-readable: "check_order must be called before process_refund"

  @dataclass
  class FSMState:
      state_id: str               # "S0", "S1", etc.
      name: str                   # "initial" | "order_verified" | "refund_processing" | "completed"
      description: str
      tools_available: list[str]  # tools that can be called from this state
      is_initial: bool
      is_terminal: bool           # conversation end states

  @dataclass
  class FSMTransition:
      from_state: str
      to_state: str
      trigger: str                # tool name or event that causes transition
      guard: str | None           # condition: "order.status == 'completed'"
      frequency: float            # observed frequency from traces (0.0-1.0)

  @dataclass
  class BehaviouralModel:
      dependency_graph: list[DependencyEdge]
      states: list[FSMState] | None           # None if no traces available
      transitions: list[FSMTransition] | None
      coverage_targets: dict                   # suggested coverage criteria for Phase B
  ```

### 8.2 Build Tool Dependency Graph

**File**: `src/graph/behavioural_model.py`

- [ ] Create `build_dependency_graph(agent_map, trace_analysis=None) -> list[DependencyEdge]`:

  **From static analysis** (already in Agent Map):
  - `dependency_analysis.dependencies` → `edge_type="requires"`, `evidence="ai_inferred"`
  - `dependency_analysis.mutually_exclusive` → `edge_type="mutually_exclusive"`, `evidence="ai_inferred"`
  - `dependency_analysis.common_sequences` → `edge_type="commonly_precedes"`, `evidence="ai_inferred"`

  **From preconditions** (Sprint 2):
  - If tool A's precondition references tool B's postcondition → `edge_type="requires"`, `evidence="static"`
  - Example: `refund_order` precondition "order must be verified" + `check_order` postcondition "order status is verified" → requires edge

  **From traces** (Sprint 7, if available):
  - Frequent bigrams → `edge_type="commonly_precedes"`, `evidence="trace_mined"`, `weight=frequency`
  - Mutually exclusive tools from traces → `edge_type="mutually_exclusive"`, `evidence="trace_mined"`

  **Merge and deduplicate**:
  - If same edge exists from multiple sources, combine evidence: `evidence="combined"`
  - Weight: static=1.0, ai_inferred=0.7, trace_mined=weight_from_frequency

### 8.3 Detect Graph Properties

- [ ] Create `analyze_graph_properties(edges: list[DependencyEdge]) -> dict`:
  - **Circular dependencies**: find cycles in the requires/commonly_precedes graph
  - **Bottleneck tools**: tools with high in-degree (many tools depend on them)
  - **Orphan tools**: tools with no edges (independent)
  - **Longest chains**: longest path through requires edges
  - **Critical paths**: paths that pass through high-risk tools

### 8.4 Infer FSM from Traces (Optional)

**File**: `src/graph/fsm_inference.py` (new file)

Only runs if Sprint 7 trace data is available.

- [ ] Create `infer_fsm(trace_conversations: list[TraceConversation], agent_map: dict) -> tuple[list[FSMState], list[FSMTransition]]`:

  **Algorithm**: k-tail state merging (simplified)
  1. For each conversation, create a sequence of tool calls
  2. Build a prefix tree (trie) of all sequences
  3. Merge states that have identical k-length suffixes (k=2 by default)
  4. Each unique prefix becomes a state
  5. Each tool call between states becomes a transition
  6. Mark initial state (before first tool call) and terminal states (after last tool call)

  **State naming heuristic**:
  - "initial": before any tool call
  - "after_{tool_name}": state after calling a specific tool
  - "completed": terminal state with successful outcome
  - "failed": terminal state with failed outcome

- [ ] Calculate transition frequencies: `count(this_transition) / count(all_transitions_from_this_state)`

## Done When

- Coverage targets are generated for Phase B
- The Agent Map includes a `behavioural_model` section
- A Mermaid state diagram is generated for the FSM

## Scope Limitations

- FSM inference requires trace data (Sprint 7). Without traces, only the dependency graph is built.
- k-tail is a simplified algorithm — it may over-merge states for complex agents. This is acceptable as a first approximation.
- The FSM is a behavioural abstraction, not a verified formal model.
